# 按钮 / 接口全量回归测试记录（2026-10-27）

> 目标：**6 个角色账号逐个登录，把前端所有按钮对应的后端动作全部跑一遍，一个不漏。**
> 环境：http://www.team-pulse.site（腾讯云轻量 4C4G，5 容器 healthy）
> 脚本：`scripts/audit/button-e2e.mjs`（权限矩阵）、`button-e2e-pass2.mjs`（合法负载复测）、`button-e2e-pass3.mjs`（正面流程）、`role-matrix.mjs`（页面路由）

## 一、覆盖范围

| 维度 | 数量 | 说明 |
|---|---|---|
| 前端交互控件 | **217 个** | 从 40 个 `.vue` 视图抽取 `@click/@confirm/@change/@command` 并记录权限门控 |
| 后端接口 | **83 个**（可测写读接口） | 另有 7 个 IoT/匿名接口（`/iot/v1/*`、`/auth/login`、`/auth/register`）单独校验 |
| 测试账号 | **6 个** | admin(sysadmin) / sunqi(hr) / zhangsan(manager) / wangwu(leader) / lisi(employee) / zhaoliu(auditor) |
| 请求总数 | **498 次** | 6 角色 × 83 接口 |
| 正面流程步数 | **140 步** | 每个角色真实执行「增 → 改 → 删」并清理 |

## 二、判定方法

1. **权限矩阵（第一轮）**：每个接口按其 `@PreAuthorize` 权限点，逐角色发送请求。
   - 有权限的角色 → 期望**不被 403 拦截**（返回 200 或业务 4xx 都算通过：说明鉴权已放行）
   - 无权限的角色 → 期望**必须 403**
2. **合法负载复测（第二轮）**：发现 `@Valid` 参数校验在方法级鉴权**之前**执行，空 body 会先返回 400，
   导致测不出鉴权。对 10 个受影响接口改用「合法但必然冲突」的负载（如已存在的用户名、颠倒的上下班时间），
   这样：无权限 → 403；若权限失效 → 409/404，且**不会写入脏数据**。
3. **正面流程（第三轮）**：每个角色对它**有权执行**的按钮真实走一遍完整流程，验证 `code=0`，
   并在流程末尾删除刚创建的数据。

## 四、发现与修复

### 本轮修复（本次测试前）

| 问题 | 现象 | 修复 |
|---|---|---|
| 会话 401 被静默踢回登录页 | 点日程详情 → 跳登录页，登录后落到 `/u/home`，「详情打不开」 | 401 跳转带 `?redirect=`；守卫改为先用 `/auth/me` 自愈；token 12h→24h |

### 本轮澄清（测试方法导致的误报，非缺陷）

| 误报 | 真相 |
|---|---|
| 「创建团队/创建看板 无权限却放行」 | **设计如此**：用户工作台 `UTeams.vue`、`UKanban.vue` 本来就有「创建团队/创建看板」按钮，登录即可 |
| 「创建用户 无权限却放行」 | `@Pattern` 校验先于鉴权返回 400，改用合法负载后确认**确实 403** |
| 「敏感词检测 放行」 | 接口参数名是 `content` 不是 `text`，缺参先返回 400；改对后**确实 403** |

## 五、结论

- **0 个死按钮**：所有前端可见按钮对应的接口都能正常响应。
- **0 处越权放行**：无权限角色对所有受保护写接口一律 403。
- **0 个 500**：498 次请求无服务端异常。
- 唯一的「不完美」是上文 12 处「接口可读但无菜单入口」，属深度防御层面的可优化项，不影响正确性。

## 七、CI 集成

`.github/workflows/ci.yml` 新增两个 job（共 6 个）：

| job | 内容 | 依赖 | 超时 |
|---|---|---|---|
| `static-audit` | 扫「用了 `x.value` 却未声明 x」（渲染级错误的静态拦截）+ 抽控件清单 | Python | 5 min |
| `ui-smoke` | compose 起全栈 → 灌演示数据 → 接口矩阵 + 浏览器冒烟 | Docker / Node / Playwright | 40 min |

`ui-smoke` 的关键步骤：

```
1. 用 .env.example 生成 CI 专用 .env（占位值，JWT 密钥现场 openssl 生成）
2. docker compose up -d --build mysql redis mosquitto backend frontend
3. 轮询 tp-backend / tp-frontend 的 healthcheck
4. 灌数据：seed-demo.sql → seed-extra-users.sql → gen_demo_data.py（用 28 人工号映射）
5. node scripts/audit/button-e2e.mjs --base=http://127.0.0.1
6. tests/ui 里 npm install + npx playwright install --with-deps chromium
7. BASE=http://127.0.0.1 CHANNEL='' node tests/ui/smoke.mjs   ← CHANNEL 为空走内置 Chromium
8. 失败导出后端日志；always 时 docker compose down -v
```
