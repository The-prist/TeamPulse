# 如何运行这个项目的页面原型

> 本文档说明三种运行方式。**只想看页面的话，用方式一，两条命令。**

---

## 0. 先看这张表，选一种方式

| 方式 | 适合场景 | 前置条件 | 启动耗时 |
|---|---|---|---|
| **方式一：一键脚本**（推荐） | 本机看页面、录屏、截图 | MySQL 8 + JDK 17 + Maven + Node 20 | 约 40 秒 |
| **方式二：手动三终端** | 想看清每一步、调试后端 | 同上 | 约 2 分钟 |
| **方式三：Docker Compose** | 部署到云服务器 / 演示完整链路（含 MQTT） | Docker + 一台 4C4G 服务器 | 首次 3~6 分钟 |

**关键认知：看页面必须有后端。** 登录、考勤看板、设备列表的数据都来自后端接口，
纯前端只能看到登录页。所以下面三种方式都是「后端 + 前端」一起起。

---

## 1. 方式一：一键脚本（推荐）

### 1.1 Windows

```powershell
# 在项目根目录（E:\codestorge）执行
.\scripts\run-local.ps1
```

默认连接 `127.0.0.1:3306`，账号 `root`，密码请自行填写（**文档里不写真实密码**）：

```powershell
.\scripts\run-local.ps1 -DbPassword 你的密码
```

脚本会依次做这些事：

1. 自动找 JDK / Maven / Node（PATH 里没有就用项目自带的 `.toolchain`）
2. 检查并释放 `8080` / `5173` 端口
3. 启动后端（首次启动会**自动建库建表**、创建管理员、创建演示打卡机）
4. 等待后端健康，再启动前端开发服务器
5. 打印访问地址和登录账号

停止服务：

```powershell
.\scripts\run-local.ps1 -Stop
```

### 1.2 macOS / Linux

```bash
chmod +x scripts/run-local.sh
./scripts/run-local.sh

# 密码不同时：
DB_PASSWORD=你的密码 ./scripts/run-local.sh

# 停止：
./scripts/run-local.sh --stop
```

### 1.3 启动完之后

打开浏览器访问 **http://127.0.0.1:5173/**

| 项目 | 地址 |
|---|---|
| 页面入口 | http://127.0.0.1:5173/ |
| 后端接口 | http://127.0.0.1:8080/api/v1 |
| 接口文档（Swagger） | http://127.0.0.1:8080/swagger-ui.html |
| 健康检查 | http://127.0.0.1:8080/actuator/health |

登录账号：

```
用户名：admin
密码：  admin123
```

> 管理员首次登录会先进入「选择面板」页（管理后台 / 用户工作台），选一次后会被记住。

## 2. 方式二：手动起三个终端

想看清每一步、或者要调后端时用这个。

### 终端 1：确认 MySQL 可用

```bash
mysql -h 127.0.0.1 -uroot -p -e "SELECT VERSION();"
```

不需要手动建库——后端连接串带了 `createDatabaseIfNotExist=true`，Flyway 会自动建表。
如果你本机没有 MySQL，用 Docker 起一个：

```bash
docker run -d --name tp-mysql -p 3306:3306 \
  -e MYSQL_ROOT_PASSWORD=<你的密码> -e MYSQL_DATABASE=teampulse mysql:8.0
```

### 终端 2：启动后端

```bash
cd backend

# Windows PowerShell
$env:DB_HOST='127.0.0.1'; $env:DB_PASSWORD='<你的密码>'
$env:MQTT_ENABLED='false'; $env:SPRING_PROFILES_ACTIVE='dev'
mvn spring-boot:run

# macOS / Linux
DB_HOST=127.0.0.1 DB_PASSWORD=<你的密码> MQTT_ENABLED=false \
SPRING_PROFILES_ACTIVE=dev mvn spring-boot:run
```

看到下面这行就成功了（还会打印演示设备的密钥，先记下来）：

```
Started TeamPulseApplication in 12.345 seconds
已创建演示打卡设备（仅用于联调，生产请删除）
  设备序列号: TP-ESP32-DEMO
  设备密钥  : d17c34ca2ff...
```

### 终端 3：启动前端

```bash
cd frontend
npm install      # 只有第一次需要
npm run dev
```

打开 http://127.0.0.1:5173/ 即可。

### 可选：模拟一次真实打卡

**再开一个终端**，用项目自带的模拟器（不需要硬件）：

```bash
# 走 HTTP 兜底通道，零依赖
node device/simulator/http-simulator.mjs \
  --sn TP-ESP32-DEMO \
  --secret <终端 2 里打印的密钥> \
  --employee E1000 \
  --loop
```

然后回到「考勤看板」页面，**5 秒内**会出现这条打卡记录。

## 3. 方式三：Docker Compose（服务器 / 完整链路）

只有这种方式会真正跑 MQTT，最接近生产形态。

```bash
cp .env.example .env && vim .env        # 修改所有 CHANGE_ME
./deploy/scripts/gen-mosquitto-passwd.sh
docker compose up -d --build
docker compose logs backend | grep -A3 演示打卡设备
```

访问 `http://服务器IP/`。详细步骤见 [README.md](../README.md) 第 4 章与
《TeamPulse 技术手册》第 6 章。

## 4. 前置条件清单

| 依赖 | 是否必需 | 说明 |
|---|---|---|
| **MySQL 8** | ✅ 必需 | 所有业务数据；没有它后端起不来 |
| **JDK 17+** | ✅ 必需 | 编译/运行后端 |
| **Maven 3.9+** | ✅ 必需 | 构建后端 |
| **Node.js 20+** | ✅ 必需 | 运行前端开发服务器 |
| Redis | ❌ 可选 | 只用于打卡报文的 nonce 去重；缺失时自动降级为内存实现 |
| MQTT Broker | ❌ 可选 | 只有真实打卡机接入才需要；缺失时后端会告警并每 30 秒重试，Web 接口不受影响 |

> Windows 上没有装 JDK/Maven/Node 时，脚本会尝试用项目自带的 `.toolchain` 目录。

## 6. 常见问题

**Q：端口 8080 / 5173 被占用怎么办？**
脚本会自动尝试释放。若占用者是其他程序，换端口：

```powershell
.\scripts\run-local.ps1 -BackendPort 8081 -FrontendPort 5174
```

**Q：提示 MySQL 连接失败？**
先确认服务在跑（`Get-NetTCPConnection -LocalPort 3306`），再用参数传正确密码。
账号密码与默认 `root` 不同时，三个都要改：`-DbUser`、`-DbPassword`（必要时 `-DbHost`）。

**Q：`/actuator/health` 返回 503？**
旧版本会因为「没有 Redis」把整体健康判为 DOWN。已在 `application-dev.yml` 里关闭 Redis 探测，
所以开发环境现在应返回 `UP`。生产 profile 仍然严格探测。

**Q：日志里有 `Flyway upgrade recommended: MySQL 8.4 is newer than...`？**
只是警告，不是错误。Spring Boot 3.2.4 自带的 Flyway 9.22 官方只测到 MySQL 8.0，
但在 8.4 上实测三个迁移脚本都能正常执行。介意的话可以把 MySQL 降到 8.0，或升级 Flyway 到 10.x。

**Q：后端启动报 `Unable to create tempDir`？**
Embedded Tomcat 需要可写的临时目录。脚本已把 `java.io.tmpdir` 指到 `backend/target/tmp`；
手动启动时可加：

```bash
mvn spring-boot:run "-Dspring-boot.run.jvmArguments=-Djava.io.tmpdir=./target/tmp"
```

**Q：接口返回的中文在我的终端里是乱码？**
数据库和接口都是正确的 UTF-8（可用 `mysql --default-character-set=utf8mb4` 或浏览器验证）。
Windows PowerShell 5.1 的 `Invoke-WebRequest` 在响应头没有 charset 时会按 Latin-1 解码，
这是**终端显示问题**，不影响页面。

**Q：页面能打开，但登录后一片空白 / 报 401？**
后端没起来或刚起来还没就绪。确认 `http://127.0.0.1:8080/actuator/health` 是 `UP` 再登录；
前端代理是否正常可以看 Network 里 `/api/v1/auth/login` 的状态码。

**Q：一定要有打卡机才能看到考勤数据吗？**
不需要。用 `device/simulator/http-simulator.mjs` 或 `.mjs` 的 MQTT 版本模拟即可；
也可以用「打卡记录」页的**手工补卡**直接造一条数据。

**Q：能不能只跑前端看页面？**
不能完整看。前端所有数据都来自后端接口，没有后端只能停留在登录页。

## 7. 想截图/录屏当作品集素材时的建议

1. 先跑一次模拟器，让考勤看板有数据（空表格不好看）
2. 「公司概览」页的图表需要日程/日志数据，可以先用界面建 2~3 条日程、1 个看板、几条日志
3. 截图建议：登录页、考勤看板（带实时流）、看板详情（卡片分列）、打卡设备（含密钥弹窗）、用户工作台首页
4. 录屏建议顺序：登录 → 选面板 → 考勤看板 → 跑模拟器 → 记录页出现新数据 → 设备页 → 规则页
