## 二、数据是怎么造的

- 打卡时间按「早到 08:40~08:55 / 正常 08:56~09:05 / 迟到 09:06~09:25」加权生成，
  下班同理（早退 / 正常 / 加班），并随机留出约 3% 缺勤，日历上能看到不同颜色的状态。
- 日汇总不是手写的，而是用 `INSERT ... SELECT ... GROUP BY` 从原始打卡聚合，
  单边打卡用 `COALESCE` 兜底，不会出现 NULL 违反 NOT NULL。
- 工号从**真实 user 表读取**（先插用户再生成打卡），避免「按 user_id 推算工号」造成错位。
- 全部使用 `INSERT IGNORE` / `ON DUPLICATE KEY UPDATE`，唯一键冲突（工号+打卡时间、
  message_id、user_id+work_date、team_id+user_id、敏感词）不会报错。

## 三、重新生成 / 重置

```bash
# 1) 重新生成 SQL（可指定日期区间与随机种子）
python scripts/docs/gen_demo_data.py --out seed-extra.sql --users users.tsv \
  --start 2026-08-01 --end 2026-10-27 --seed 20261027

# 2) 应用到某个库
docker exec -i tp-mysql mysql -uroot -p<密码> teampulse < seed-extra.sql
```

`users.tsv` 是工号映射（`user_id|employee_no|role|department_id|username|nickname`），
从库里导出：

```bash
docker exec tp-mysql mysql -uroot -p<密码> -N -B teampulse -e \
"SELECT CONCAT_WS('|', user_id, IFNULL(employee_no,'NONE'), role, IFNULL(department_id,0), username, IFNULL(nickname,''))
 FROM user WHERE deleted = 0 ORDER BY user_id;"
```

### ⚠️ 重复执行的注意事项

- **幂等**：`user`、`team_member`、`attendance_record`、`attendance_daily`、`makeup_request`（部分）、
  `sensitive_word` 有唯一键兜底，重复执行不会重复插入。
- **非幂等**：`schedule`、`worklog`、`comment`、`kanban_item`、`audit_log` 没有业务唯一键，
  重复执行会**再插一遍**。要重灌请先清空这几张表的演示数据，最简单是在全新库里执行。

## 四、本次造数顺带修的数据问题

| 问题 | 现象 | 处理 |
|---|---|---|
| `zhouba` / `wujiu` 的 `password` 存的是明文 `123456` | BCrypt 校验必然失败，账号登不进去 | 统一替换为 BCrypt 散列（`pwd LIKE '$2%'` 之外的行） |
| `team.creator_id` 可能为空 | 该列 NOT NULL，为空时团队页报错 | 兜底更新为有效用户 |
| 联调期残留 `probe-kanban` | 演示时出现一块奇怪的板 | 连同其列与卡片一并删除 |
| `audit_log.created_at` 被插成 `0000-00-00` | JDBC 抛 `Zero date value prohibited`，审计接口 **500** | 删除坏行后带 `created_at` 重插，`result` 只用 `SUCCESS`/`FAILURE` |

> 最后一条是真实缺陷：造数漏填 NOT NULL 且无默认值的列，就会写出零日期，
> 业务接口直接 500。生成脚本已修正并写了注释。
