# 登录体验与登录安全增强说明（2026-10-28）

> 正式文档：`docs/TeamPulse_登录体验与登录安全增强说明.docx`（13 页，含 6 张实拍截图与 22 张表）
> 本文是它的 Markdown 摘要，便于在仓库里直接检索与 diff。

## 一句话概括

本轮把「用户打开系统后的第一分钟」补齐：登录页按真实时间与真实天气渲染天空、雨雪会在页面里堆积、
登录失败/成功都有反馈与转场、连续失败要过服务端验证码、面板选择页支持暗色并用圆形转场切换。

## 1. 登录页天空系统

| 能力 | 实现 |
|---|---|
| 太阳 / 月亮位置 | `utils/solar.js` 的 `sunPosition()` / `moonPosition()`，含大气折射 |
| 月相 | `moonIllumination()` + 8 个中文相名 |
| 天色 | `skyPalette(高度角, 是否上午)`，按 −18°…90° 打关键帧，晨昏两套色阶 |
| 日月同弧 | `arcPos()`，东左西右；y 方向用 sin 的 0.62 次幂压扁（避免正午被卡片挡） |
| 云 | 7 个 SVG，运行时按「时段 × 天气」重上色；DOM `<img>` 渲染 |
| 云漂移 | 向右 0.16px/帧 ≈ 10px/s；出右侧换形状从左侧进场；长云带两张拼接无缝循环 |
| 流星 / 飞机 | 夜间流星、白天飞机尾迹，间隔 ≥1 分钟 |

**火烧云只在「少云/多云」的傍晚出现**；阴、雨、雪、雾、雷暴的傍晚用灰紫/灰褐。
**夜间云不会消失**，只是压暗并统一用夜间色板。

## 3. 积水与积雪

- **雨 → 积水**：水位最高涨到登录卡片下沿；水面有正弦波纹与高光；与卡片下沿之间画弯月面。
- **雨点溅水花**：打到水面即消失并溅起涟漪 + 1~2 颗水珠，寿命 0.42~0.58s，透明度 `(1−k)^1.5`。
- **雪 → 积雪**：底部雪堆（上表面更平整）+ 卡片顶部雪盖（沿卡片顶边曲线每 3px 采样，含 18px 圆角，厚度 3~22px）。
- 切天气时堆积**立即清零**（早期按慢速排干，要 15 分钟，看着像没消失）。
- 叠加层每帧必须 `clearRect`：早期漏了这一步，水/雪逐帧叠加变厚，切走天气也擦不掉。

## 4. 访客定位与实时天气

```
浏览器 → nginx（写 X-Real-IP）→ Spring Boot
        ├─ ipwho.is         IP → 城市/省/经纬度
        ├─ Open-Meteo       云量 / WMO 天气码 / 降水 / 气温
        └─ 返回 {source, ipCity, province, city, district, lat, lon, cloudCover, weatherCode, precipitation, temperature}
```

- **隐私**：原始 IP 只在单次请求内存中使用；缓存键是「进程启动随机盐 + SHA-256」摘要，不落库。
- **缓存**：天气 10 分钟、IP 归属 30 分钟、地名坐标 24 小时；前端进页面取一次 + **每 10 分钟自动重取** + 回前台若超 5 分钟补取。
- **手动选区**：登录卡蓝色区域的「修改」弹出省/市/区三级级联，结果存 localStorage，另有「恢复 IP 定位」。
- **降级**：任一步失败回落北京 + 多云，页面照常渲染。

### 地名解析踩过的坑（都已修）

1. geocoder 认「杭州」不认「杭州市」→ 原名查空后剥后缀重试。
2. 「上海市」模糊命中河南洛阳的「上海市场社区」→ 原名与去后缀名**合并候选**再挑。
3. 「长春市」被黑龙江一个叫「长春」的村子顶掉 → 评分改为「按原样精确 > 去后缀精确 > 前缀 > 人口」。
4. 同名区县（十几个「朝阳」）→ 先定城市坐标，再取离城市最近者，>150km 视为同名异地。

## 5. 登录交互

- **失败变红**：只要「点了登录没进去」就变红（含账号/密码没填、验证码没过、接口报错），红色 `#d64545`，560ms 复原；不含抖动。
- **成功转场**：从登录按钮升起顶层纯色圆 → `clip-path` 扩散 440ms → 切路由 → 等两帧 → 收缩 360ms → 移除节点。底色取目标主题页面底色，切换不闪。
- **主题按时间**：6:00–18:00 亮色，其余暗色；用户点过左下角切换即置 `tp_theme_manual=1`，此后手动优先。
- 左下角切换按钮与它的原动效都保留。

## 6. 登录安全：服务端滑块验证码

| 步骤 | 接口 | 说明 |
|---|---|---|
| 出题 | `GET /api/v1/public/captcha` | AWT 现画底图 + 挖缺口 + 裁拼图块，返回 token 与两张 base64 PNG；3 分钟过期，**答案不下发** |
| 校验 | `POST /api/v1/public/captcha/verify` | `{token, offset}`，误差 ≤6px 通过；一题只判一次；通过发一次性 ticket（HMAC，3 分钟，用后作废） |
| 登录 | `POST /api/v1/auth/login` | 请求体新增可选 `captchaTicket`；服务端判定需要时校验并消费 |

- **失败限流**：账号与 IP 两条线分别计数，5 次 / 15 分钟窗口；任一超限要求验证码；登录成功清零。
- **错误码**：`40101 LOGIN_CAPTCHA_REQUIRED`（HTTP 423）、`40102 CAPTCHA_INVALID`（HTTP 400）、
  `40103 LOGIN_IP_BLOCKED`（HTTP 429，含剩余分钟数）。
- **交互**：弹窗 `destroy-on-close` + `@open` 重置，第二次打开是新题（缺口坐标实测 162 → 202）。

### 粘性验证码（触发后每错一次验一次）

| 阶段 | 行为 |
|---|---|
| 前 5 次失败 | 40100，正常计数 |
| 第 6 次起 | 40101，要求验证码；**未过验证码的请求也计入失败次数** |
| 验证通过 | 只对紧接着这一次登录有效（ticket 一次性） |
| 登录成功 | 计数清零 |

### IP 拉黑

- 同一 IP 累计 10 次失败（含未过验证码的尝试）→ **拉黑 10 分钟**，期间直接 40103。
- 黑名单**不存原始 IP**：键是「进程启动随机 32 字节盐 + SHA-256」摘要，重启即失效。
- 日志脱敏：登录失败/需要验证码/拒绝登录三条日志只打印 `ipDigest` 前缀。
- 按 IP 隔离：服务器本机被拉黑返回 40103 时，另一台机器（不同公网 IP）仍返回 40100。

### 忘记密码提示

首次触发验证码后，弹窗内与表单下方都显示「忘记了您的密码？请联系您的主管或服务器管理员重置密码。」
当前只有管理员重置入口（`PUT /api/v1/user/{id}/password`，需 `user:manage`），没有自助找回与邮件通道。

### 安全边界（如实）

- 这类滑块验证码**能被图像配准破解**（本项目测试即用归一化互相关，相关系数 0.67~0.70）。它抬高成本，不是绝对防线。
- 计数、题目、ticket 都在**进程内存**：单实例可用，重启清零；多实例必须换 Redis。
- 账号锁定、MFA、WAF 均**未实现**。

## 7. 面板选择页

- 配色改走 `--tp-*` 变量，暗色下标题/副标题/选项对比度 8.77~15.72:1。
- 踩坑：`.subtitle` 撞上 `dark-fixes.css` 里全局 `html.dark .subtitle { color: … !important }`，scoped 规则失效 → 改名 `.entry-sub`。
