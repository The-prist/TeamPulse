# TeamPulse 部署手册（Runbook）

> 适用版本：`main` @ 2026-10-27（Flyway V1~V7）　目标环境：单台 4C4G Linux 云服务器
> 本文是**可照着敲**的操作手册；踩坑过程与验证数据见 [`部署验证记录.md`](./部署验证记录.md)。

---

> **关于 CI**：本仓库的 GitHub Actions 目前不运行（账号账单锁定，已按决策终止推进）。
> 上线前请在本地执行 `scripts/run-tests.ps1` 做等价验证（单测 + 前端构建 + 46 项接口断言）。

## 0. 前置检查（5 分钟）

| 项 | 要求 | 检查命令 |
|---|---|---|
| 操作系统 | Ubuntu 22.04 / 24.04（或同内核发行版） | `lsb_release -a` |
| 配置 | 2C4G 起（推荐 4C4G） | `nproc && free -h` |
| 磁盘 | ≥ 20GB 可用（镜像 + 数据 + 日志） | `df -h /` |
| 网络 | 能访问 Docker Hub 或其镜像源 | `curl -sI https://registry-1.docker.io/v2/ \| head -1` |
| 端口 | 80、1883、（可选 443、9090、3000）未被占用 | `ss -lntp \| grep -E ':(80\|1883\|443)'` |
| 权限 | 有 sudo | `sudo -v` |

> 若 Docker Hub 不可达（国内常见），先按第 2 节配镜像源。

## 1. 安装 Docker（首次）

```bash
# 官方脚本（国内可用阿里云镜像源脚本替代）
curl -fsSL https://get.docker.com | sudo sh

# 允许当前用户免 sudo
sudo usermod -aG docker $USER && newgrp docker

# 验证
docker version --format '{{.Server.Version}}'
docker compose version
```

**验收**：两条命令都能输出版本号。

---

## 2. 配置镜像加速（国内强烈建议）

```bash
sudo mkdir -p /etc/docker
sudo tee /etc/docker/daemon.json >/dev/null <<'JSON'
{
  "registry-mirrors": [
    "https://docker.m.daocloud.io",
    "https://docker.1ms.run",
    "https://hub.rat.dev"
  ],
  "log-driver": "json-file",
  "log-opts": { "max-size": "50m", "max-file": "3" }
}
JSON

sudo systemctl restart docker

# 验收：能看到 mirror 列表，且能拉镜像
docker info --format '{{range .RegistryConfig.Mirrors}}{{.}} {{end}}'
docker pull hello-world
```

> `log-opts` 限制容器日志大小，避免长期运行把磁盘写满（默认 json-file 无限增长）。

## 3. 拉取代码与配置环境变量

```bash
git clone git@github.com:The-prist/TeamPulse.git
cd TeamPulse

cp .env.example .env
```

编辑 `.env`，逐项确认（**所有 `CHANGE_ME` 必须改**）：

| 变量 | 说明 | 生成方式 |
|---|---|---|
| `MYSQL_ROOT_PASSWORD` | MySQL root 密码 | `openssl rand -base64 24` |
| `REDIS_PASSWORD` | Redis 密码 | 同上 |
| `MQTT_USERNAME` / `MQTT_PASSWORD` | 设备接入账号 | 用户名自定义，密码随机 |
| `JWT_SECRET` | JWT 签名密钥，**≥32 字节** | `openssl rand -hex 32` |
| `TPP_ADMIN_PASSWORD` | 初始管理员密码（首次启动后请改） | 自定义强密码 |
| `GRAFANA_ADMIN_PASSWORD` | Grafana 管理员密码（仅启用监控时） | 自定义强密码 |
| `TPP_CORS_ORIGINS` | 允许的前端来源，同源部署可留空 | — |

**验收**：`grep -c CHANGE_ME .env` 输出 `0`。

> `application-prod.yml` 与 compose 都做了 **fail-closed**：漏配 `JWT_SECRET` 或 `TPP_ADMIN_PASSWORD` 时直接启动失败，不会静默用开发默认值。

## 5. 首次启动

```bash
docker compose up -d --build
```

首次会依次：拉基础镜像 → 构建后端（Maven 下载依赖，**5~6 分钟**）→ 构建前端（~40s）→ 起 5 个容器 → Flyway 执行 V1~V7 → 创建管理员与演示设备。

```bash
# 观察启动过程
docker compose logs -f backend
```

**验收（关键）**：

```bash
# 1) 5 个容器全部 healthy（等 60~90 秒）
docker compose ps

# 2) 健康检查
curl -s http://127.0.0.1/actuator/health          # {"status":"UP"}

# 3) 前端可访问
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1/    # 200

# 4) 迁移到位
docker exec tp-mysql mysql -uroot -p"$MYSQL_ROOT_PASSWORD" teampulse \
  -e "select version,success from flyway_schema_history order by installed_rank"

# 5) 管理员可登录
curl -s -X POST http://127.0.0.1/api/v1/auth/login \
  -H 'Content-Type: application/json' \
  -d "{\"username\":\"admin\",\"password\":\"$TPP_ADMIN_PASSWORD\"}" | head -c 200
```

登录响应里应包含 `"role":"sysadmin"`、22 个 `permissions`、`"dataScope":"ALL"`。
**若 `permissions` 为空，说明用户角色不是 6 个角色 key 之一**——检查 V7 是否执行、`user.role` 是否为 `sysadmin`。

## 7. 设备接入

| 步骤 | 操作 |
|---|---|
| 1 | 后端启动日志里找到演示设备的 SN 与密钥：`docker compose logs backend \| grep -A3 演示打卡设备` |
| 2 | 把两者写入固件 `device/esp32/attendance_node/secrets.h`（`DEVICE_SN` / `DEVICE_SECRET`） |
| 3 | 固件的 `MQTT_HOST` 改为服务器公网 IP，`MQTT_USERNAME/PASSWORD` 用 `.env` 里的值 |
| 4 | 云安全组放行 `1883`（或启用 TLS 后的 `8883`） |

```bash
# 验收：模拟器能打通
cd device/simulator
node http-simulator.mjs --server http://<服务器IP> --sn <SN> --secret <SECRET> --employee-no E1001
```

成功后 `curl http://127.0.0.1/api/v1/attendance/recent?size=5`（带 token）能查到该记录。

## 8. 配置 HTTPS（有域名时）

```bash
# 1) 申请证书（以 certbot 为例）
sudo apt install -y certbot
sudo certbot certonly --standalone -d your-domain.com

# 2) 拷贝到项目（compose 已预留挂载点，按需在 compose 里加 volume）
mkdir -p deploy/certs
sudo cp /etc/letsencrypt/live/your-domain.com/fullchain.pem deploy/certs/
sudo cp /etc/letsencrypt/live/your-domain.com/privkey.pem  deploy/certs/
sudo chmod 644 deploy/certs/*.pem

# 3) 打开 frontend/nginx.conf 里被注释的 443 server 块，填域名与证书路径
#    并把 80 的 server 改成 301 跳转（文件里已有示例）
```

改完重建前端容器：`docker compose up -d --build frontend`

**验收**：`curl -sI https://your-domain.com/ | head -1` 返回 200/301；浏览器无证书告警。

## 9. 启用监控（可选但推荐）

```bash
# 在 .env 里设置 GRAFANA_ADMIN_PASSWORD，然后：
docker compose --profile monitoring up -d prometheus grafana
```

| 服务 | 地址 | 说明 |
|---|---|---|
| Prometheus | `http://127.0.0.1:9090` | 抓取 `backend:8080/actuator/prometheus`，每 15s 一次 |
| Grafana | `http://127.0.0.1:3000` | 预置数据源 + 「TeamPulse 概览」看板，账号 `admin` / `GRAFANA_ADMIN_PASSWORD` |

**验收**：Prometheus → Status → Targets，`teampulse-backend` 为 **UP**；Grafana 首页能看到预置看板且有曲线。

> 两个端口默认只绑 `127.0.0.1`。要从外网看，用 SSH 隧道：`ssh -L 3000:127.0.0.1:3000 user@server`，**不要**直接把 3000/9090 暴露到公网。

## 10. 日常运维

```bash
# 发布（先备份 → 重建有变化的镜像 → 滚动上线 → 健康轮询）
./deploy/scripts/deploy.sh

# 只重启后端
docker compose restart backend

# 看日志（容器内日志同时写入 backend-logs 卷）
docker compose logs -f --tail=100 backend

# 数据库备份
./deploy/scripts/backup.sh              # 产出 deploy/backups/teampulse-YYYYmmdd-HHMMSS.sql.gz
```

**建议加一条 crontab**（每天 03:30 备份，保留 14 天）：

```bash
crontab -e
30 3 * * * cd /opt/TeamPulse && ./deploy/scripts/backup.sh >> /var/log/teampulse-backup.log 2>&1
```

## 11. 回滚

| 场景 | 操作 |
|---|---|
| 只回滚代码 | `git checkout <上一个 commit> && docker compose up -d --build backend frontend` |
| 回滚镜像 | `docker compose down && docker compose up -d`（compose 用 `image:` 固定 tag，可先在 CI 打多 tag） |
| **需要回滚数据** | 先停后端：`docker compose stop backend` → 恢复备份（见 §12） → 再启动 |

> 迁移不可回退：Flyway 只前进。若新版本包含破坏性迁移，必须**先备份再升级**，回滚时连同数据库一起恢复。

## 12. 备份与恢复演练（上线前必做一次）

```bash
# ---- 备份 ----
./deploy/scripts/backup.sh
ls -lh deploy/backups/ | tail -3

# ---- 演练：删数据 → 恢复 → 验证 ----
docker exec tp-mysql mysql -uroot -p"$MYSQL_ROOT_PASSWORD" teampulse \
  -e "select count(*) from attendance_record"          # 记下当前条数
docker exec tp-mysql mysql -uroot -p"$MYSQL_ROOT_PASSWORD" teampulse \
  -e "delete from attendance_record where id > 0"      # 模拟误删

# 恢复（备份是 gzip 的 mysqldump）
gunzip -c deploy/backups/<备份文件>.sql.gz | \
  docker exec -i tp-mysql mysql -uroot -p"$MYSQL_ROOT_PASSWORD" teampulse

docker exec tp-mysql mysql -uroot -p"$MYSQL_ROOT_PASSWORD" teampulse \
  -e "select count(*) from attendance_record"          # 应恢复到原条数
```

**验收**：恢复后条数与删除前一致；再访问前端能看到历史打卡。

## 13. 故障排查表

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 容器 `Restarting` 循环 | 配置错误（如 mosquitto 用了 bridge 参数） | `docker compose logs <服务> --tail 50` 看第一条 ERROR |
| 后端启动失败，日志提到 JWT | `.env` 的 `JWT_SECRET` 缺失或不足 32 字节 | 重新 `openssl rand -hex 32` |
| 管理员能登录但菜单全空 | 用户角色不是 6 个 key 之一 → 权限为 0 | 检查 `user.role`；确认 V7 已执行 |
| 前端 502 / 504 | 后端未 healthy | `docker compose ps` + `logs backend` |
| `/actuator/health` 返回 400 | 反向代理没转发 Host 头 | nginx location 加 `proxy_set_header Host $host;` |
| 设备连不上 MQTT | 安全组未放行 1883 / 密码文件不匹配 | `docker exec tp-mosquitto mosquitto_sub -t '#' -v -u <user> -P <pwd>` 自测 |
| 磁盘满 | 容器日志/备份堆积 | `docker system df`；确认 daemon.json 的 log-opts 生效 |
| 时间不对导致考勤判定异常 | 容器时区 | 已在 compose 设 `TZ=Asia/Shanghai` 与 `-Duser.timezone` |

**排障顺序**：容器是否 healthy → 后端日志错误码 → 数据库是否有数据 → 反向代理是否转发 → 网络/安全组。
